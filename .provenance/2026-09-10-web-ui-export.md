# Web UI Export Provenance

## Trigger

The user asked to add an export button to the web UI so users can export the current report as JSON or Markdown. The exported data and report format should match `scan`, or be enhanced only where needed to align with the web experience.

The user later clarified the interaction: the format choice should appear only after clicking `Export`, and choosing a format should immediately download the file.

This provenance record was requested after the implementation was completed, so it records the implemented intent and decisions as a structured summary rather than a pre-implementation transcript.

## Scope

This record covers static and live web export behavior:

- `internal/report/report.html`

- `internal/report/report.go`
- `internal/report/report_test.go`
- `internal/live/live.go`
- `internal/live/live_test.go`

## Conversation Summary

The existing scan path writes a report directory containing `snapshot.json` and `summary.md`. The web UI already embeds the snapshot for rendering, but did not expose a download workflow.

The implementation adds an `Export` control to the embedded report UI. Clicking `Export` opens a small menu with `JSON` and `Markdown` options. Selecting an option immediately downloads the chosen format.

For static reports, the page downloads the embedded snapshot JSON and an embedded Markdown summary generated by the same Go report code used for `summary.md`. For live reports, the browser calls read-only export endpoints that render the current server-side snapshot as `snapshot.json` or `summary.md`.

## Design Diff

- `internal/report/report.html`: adds an export menu, client-side download helper, static export support, and live export requests.
- `internal/report/html.go`: adds snapshot JSON rendering for reuse, embeds Markdown summary text in static HTML, and clears the Markdown placeholder for live HTML.
- `internal/report/report.go`: renders static `index.html` with the same target used for `summary.md` so Web Markdown export matches scan artifacts.
- `internal/live/live.go`: adds `/api/export/snapshot.json` and `/api/export/summary.md` endpoints over the current published snapshot.
- `internal/report/report_test.go`: verifies export controls, placeholders, and embedded Markdown.
- `internal/live/live_test.go`: verifies export endpoint behavior before and after a snapshot is available.

## Decisions

- Keep `Export` as the only always-visible control; show JSON and Markdown choices only after the user clicks it.
- Download immediately after the user chooses a format.
- Reuse Go report generation for Markdown to avoid duplicating scan formatting in browser JavaScript.
- Keep live export endpoints read-only and backed by the already published in-memory snapshot.
- Return `503` from live export endpoints before the first snapshot is available.

## Rejected Alternatives

- A permanently visible export format selector was rejected because it made the toolbar heavier and did not match the clarified interaction.
- Reimplementing the full Markdown formatter in JavaScript was rejected because it would diverge from `scan` over time.
- Triggering a new scan from export was rejected because live HTTP reads should not initiate collection.

## Constraints

- Static HTML reports must remain self-contained and usable offline.
- Live server endpoints must remain read-only.
- Markdown output should match `scan` report formatting.
- JSON output should use the same complete snapshot shape as `scan`'s `snapshot.json`.
- Existing filters, theme toggle, and topology interactions must keep working.
